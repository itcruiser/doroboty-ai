# Restore deepening generation on Netlify

## Intent

The deployed static frontend sends aspect generation to `/api/deepening/aspects`, which returns 404 because the deployment has no functions. The user requested a fix and deployment. Netlify already has production `OPENAI_API_KEY` and `OPENAI_MODEL` secrets with Functions scope; do not read, copy or expose their values.

## Acceptance criteria

- Serve the existing aspect and question API routes through a modern TypeScript Netlify Function, outside the static publish directory.
- Share provider generation, prompts, strict schemas and professional/public input projection with the local companion; preserve the local transport and static fallback behavior.
- Keep credentials server-only, logs free of text/secrets, responses uncached, requests bounded and generation timed out. Reject cross-origin requests and apply a platform IP rate limit for this public synthetic-data demo; role selection remains a simulation, not authentication or a spending cap.
- Test both routes and rejection/recovery paths using mocked provider calls, without API charges in automated tests. Typecheck the actual function entry and include it in the stage-safe upload package.
- Update current behavior, architecture, security and publication guidance to distinguish local/static and hosted generation.
- Run `./scripts/verify`, review the diff separately, deploy to the existing Netlify project and verify actual aspect generation through the offer editor using synthetic content. Verify questions and preserve human approval.
