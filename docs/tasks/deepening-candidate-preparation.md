## Recovery decision

The user clarified that the failure appears immediately on entering step 2 and needs the flow repaired, not an instruction to supply text to the agent. Add an explicit in-session professional-fact confirmation surface when automatic preparation fails. The candidate selects from the existing finite professional facts and confirms generation. This is a human-prepared replacement for the AI input only: it never changes the submitted step-1 answer and never sends raw prose. Without recognized or explicitly approved facts, there is still no HTTP/model request. Automatic unsafe-input blocking and unsafe-CV omission remain. Confirmed facts stay in the mounted session, are invalidated after changing step-1 text, and never persist in drafts/exports. Existing decided questions remain untouched; only undecided questions may regenerate. This extends the recovery interaction without relaxing the transport allowlist.

Public test seams remain those already agreed in the supplied spec/implementation contract: generation client HTTP boundary and browser application routes. Use existing Base UI Checkbox/Button, C04 fieldset/legend and C17 recovery/C22 reading roles inside the existing sheet. No new card/control/font family or kit edit. Verify no default selection or automatic request, keyboard/mobile, identity/raw-CV omission, one final application, decided preservation, and refresh loss.
